# 네이버 플레이스 영업 DB 수집기

지역 기반 소상공인 영업을 하는 광고대행사, POS/키오스크 영업자, 식자재 유통업체를 위한 **영업 DB 엑셀 수집 도구**입니다.

GUI 실행 진입점인 `app.py`를 기준으로 동작합니다. 공식 법정동 데이터를 기준으로 시도·시군구·법정동(다중 선택, 가나다순 표시)과 키워드를 선택하면 검색 조합을 자동으로 생성하고, 브라우저가 검색 과정에서 정상적으로 수신한 목록 응답을 처리해 업체 데이터를 Excel로 저장합니다.

본 프로그램은 네이버 공식 제품이거나 네이버와 제휴한 제품이 아닙니다.

---

## 1. 소개

- GUI 기반 실행(`app.py`), Windows 전용.
- 지역(행정안전부 공식 법정동 Snapshot 기반 시도 + 시군구 + 법정동 다중 선택) + 키워드 선택 → 검색 조합과 전체 목표 저장 개수를 자동 생성합니다.
- 브라우저가 검색 과정에서 정상적으로 수신한 응답을 처리해 업체 목록 데이터로 변환합니다. 별도의 HTTP 클라이언트로 네이버 엔드포인트를 직접 호출하는 구조는 사용하지 않습니다.
- 검색 결과 목록 화면만 사용하며, 카드를 클릭해 상세 화면으로 진입하지 않습니다.
- CAPTCHA·요청 제한(429) 감지 시 우회하지 않고 즉시 중단하며, 그때까지 수집된 결과가 있으면 저장합니다.

---

## 2. 주요 기능

- 지역(시도/시군구/법정동) + 키워드로 검색 조합을 자동 생성
- 검색 조합 내부 중복 제거(검색 조합당 수집 상한) → 전체 검색 조합 전역 중복 제거(전체 목표 저장 개수) 2단계 중복 제거
- 지역·새로오픈·리뷰 수 필터(§4)
- 전체 목표 저장 개수에 도달하거나 선택한 검색 조합을 모두 실행하면 자동 종료
- 일시정지·재개·중지 지원
- Excel 저장을 통한 즉시 영업 활용

## 3. 수집 모드

화면 "6. 수집 모드"에서 두 가지 중 하나를 선택합니다.

| 모드 | 설명 | 소요 시간 |
|---|---|---|
| 빠른 기본 수집 | 검색 목록 응답만으로 업체명·업종·리뷰수·주소·전화 등 핵심 정보를 수집합니다. | 상대적으로 빠름 |
| 홈페이지·SNS 포함 수집 | 기본 수집 후 업체별 홈페이지 보강 단계가 추가로 붙습니다. | 업체 수에 따라 더 걸림 |

### 홈페이지·SNS 포함 수집 상세

- 목록 수집이 모두 끝나고 전역 중복 제거까지 마친 **뒤에만** 별도 단계로 실행됩니다. "빠른 기본 수집" 모드에서는 이 단계 자체가 호출되지 않으며 홈페이지 요청이 0회입니다.
- 고유 업체(place_id)마다 홈페이지 상세 정보를 동시성 2로 요청합니다. 1차 시도에서 실패한 업체 중 일시적 오류(타임아웃/5xx/빈 응답 등)만 안정화 대기 후 동시성 1로 **업체당 최대 1회** 재시도합니다(즉, 업체당 최대 요청 2회). 1차 실패율이 대상 수의 10%를 초과하면 재시도 자체를 진행하지 않습니다.
- CAPTCHA·HTTP 403/405/429가 감지되면 재시도하지 않고 신규 요청을 즉시 중단합니다(이미 처리된 결과와 아직 처리하지 않은 원본 목록 결과는 그대로 보존·저장).
- **상세 처리 성공과 "외부 링크 발견"은 같은 의미가 아닙니다.** 업체가 홈페이지·SNS를 실제로 등록하지 않아 4개 링크 컬럼이 전부 빈칸이어도 처리 자체는 정상 성공입니다.
- 목록 단계에서 이미 확정된 핵심 필드(업체명·업종·리뷰수·주소·플레이스 URL·수집일)는 홈페이지 보강이 절대 덮어쓰지 않습니다. 채워지는 값은 홈페이지·인스타·블로그·추가 링크와, 목록에서 공란이었던 대표전화뿐입니다.
- 최종까지 실패한 업체도 목록 단계에서 확보한 값 그대로 Excel 행에 남습니다(행 삭제 없음).
- 모든 시도 기록과 최종 실패 업체 목록은 `logs/diagnostics/home_enrichment_<실행시각>.json`에 저장됩니다. 쿠키/토큰/HTML 원문은 저장하지 않습니다.

## 4. 지원 필터

- **지역**: 시도 + 시군구(콤보박스 단일 선택) + 법정동(팝업, 다중 선택, 가나다순). 법정동을 하나도 선택하지 않으면 시군구(시군구 없는 지역은 시도) 단위로 검색합니다. 네이버가 반환하는 주소를 선택한 공식 지역과 비교하는 지역 exact 필터가 적용되어, 선택 지역 밖의 결과는 이 필터 단계에서 먼저 제외되고 목표 개수 계산에 반영되지 않습니다(전체 목표 저장 개수를 실제보다 적게 채우는 원인이 되지 않음). 네이버 표기가 공식 명칭과 다른 경우는 실측된 사례에 한해서만 같은 지역으로 인정합니다.
- **새로오픈 업체만 수집**: 체크하면 네이버가 제공하는 새로오픈 전용 목록만 수집합니다. 일반 목록으로 조용히 대체하지 않으며, 새로오픈 업체 수가 목표보다 적으면 실제 확보된 개수로 정상 종료됩니다(오류 아님).
- **리뷰 수(최소~최대)**: 화면 "3. 필터"의 리뷰 수 입력란에 값을 넣으면 총리뷰수 기준으로 범위 밖 업체를 제외합니다. 비워두면 제한이 없습니다. 이 필터는 지역·새로오픈 필터와 함께 목록 수집 단계에서 적용되며, 제외된 업체는 검색 조합당 수집 상한을 소비하지 않습니다.

## 5. 설치

```powershell
# 1. 가상환경 생성
python -m venv .venv

# 2. 의존성 설치(.venv 실행 파일 기준 - 활성화 여부와 무관하게 동작)
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 3. Playwright 브라우저 설치
.\.venv\Scripts\python.exe -m playwright install chromium
```

가상환경을 활성화해 사용하려면 `.\.venv\Scripts\Activate.ps1` 실행 후 `python`/`pip` 명령을 그대로 사용해도 됩니다.

주요 의존성(`requirements.txt` 기준): `customtkinter`(GUI), `playwright`(브라우저 자동화), `pandas`/`openpyxl`(Excel 저장), `python-dotenv`(개발자용 `.env` 로딩), `pyinstaller`(EXE 빌드).

> Python 최소 지원 버전은 코드로 강제되지 않았습니다. 개발 환경은 Python 3.14 계열을 사용합니다.

### Windows Native Browser + CDP

기본 브라우저 backend는 Playwright 번들 Chromium을 직접 띄우는 방식이 아니라, **Windows에 설치된 Microsoft Edge 또는 Google Chrome을 백그라운드로 실행한 뒤 CDP(Chrome DevTools Protocol)로 연결하는 방식**입니다.

- **요구사항**: Microsoft Edge 또는 Google Chrome 중 하나 이상이 설치되어 있어야 합니다(대부분의 Windows 10/11에는 Edge가 기본 설치되어 있음). 둘 다 찾지 못하면 Playwright 번들 Chromium으로 조용히 대체하지 않고, 탐색한 경로와 해결 방법이 포함된 오류를 표시합니다.
- **전용 profile**: 사용자의 평소 Edge/Chrome 프로필이 아니라 `%LOCALAPPDATA%\NaverPlaceSalesDbCrawler\browser_profiles\{edge|chrome}` 전용 프로필을 사용합니다. 동일 프로필을 두 프로세스가 동시에 사용하려 하면 `profile_in_use` 오류로 명확히 차단됩니다.
- **정상 종료**: 프로그램이 직접 실행한 브라우저 프로세스만 종료합니다. 이미지 이름으로 모든 Edge/Chrome 창을 닫는 방식은 쓰지 않으므로, 평소 쓰던 Edge/Chrome 창에는 영향이 없습니다.
- **개발·테스트용 fallback**: 환경 변수 `PCCRAWLER_BROWSER_BACKEND=launch`로 Playwright 번들 Chromium 실행 방식으로 명시적으로 전환할 수 있습니다(배포 EXE에서는 이 환경 변수가 무시되고 항상 CDP 방식이 사용됩니다). 프로덕션 배포 시에는 사용하지 않습니다.
- **문제 해결**:
  - `BrowserExecutableNotFoundError`: Edge 또는 Chrome을 설치하거나, 환경 변수 `PCCRAWLER_BROWSER_PATH`로 실행 파일 경로를 직접 지정하세요.
  - `profile_in_use`: 이미 실행 중인 다른 수집 프로세스가 끝날 때까지 기다린 뒤 다시 시도하세요.
  - `CdpStartupError`(CDP 준비 실패/timeout): 브라우저가 비정상 종료되었거나 포트가 막혀있을 수 있습니다. 잠시 후 다시 시도하세요.
- 이 방식이 모든 환경·검색어에서 차단을 우회한다는 의미는 아닙니다. CAPTCHA·403·405·429 감지와 안전 중단 정책은 이 backend 선택과 무관하게 그대로 유지됩니다(§9).

## 6. 실행

```powershell
.\.venv\Scripts\python.exe app.py
```

실행 후 화면 "DB 수집" 탭에서 지역·키워드·필터·수집 모드를 선택하고 "수집 시작"을 누릅니다.

## 7. 사용 방법

1. **지역 선택**: 시도 → 시군구(콤보박스) 선택 후 "법정동 선택" 버튼으로 팝업을 열어 법정동을 다중 선택합니다(전체 선택/해제 제공, 가나다순 표시). 법정동을 선택하지 않으면 시군구 단위로 검색합니다.
2. **키워드 입력**: 검색할 업종/검색어를 1개만 입력합니다(다중 키워드는 지원하지 않습니다).
3. **필터**: 새로오픈 업체만 수집 여부, 리뷰 수 최소~최대(§4)를 설정합니다.
4. **검색 조합당 수집 상한**: 검색 조합 하나당 최대 수집 개수를 입력합니다(기본값 30).
5. **전체 목표 저장 개수**: 검색 조합당 수집 상한 × 검색 조합 수로 항상 자동 계산되며 직접 입력할 수 없습니다(기본값 예시 300). 최대 목표값이며 보장값이 아닙니다.
6. **수집 모드**: "빠른 기본 수집" 또는 "홈페이지·SNS 포함 수집" 중 하나를 선택합니다(§3).
7. **수집 시작**을 누르면 진행률·ETA·현재 상태가 화면에 표시됩니다. **일시정지/재개**, **중지**, 완료 후 **저장 폴더 열기**를 사용할 수 있습니다.

앱에는 "안내·정책" 탭에 핵심 수집 정책 요약이 포함되어 있습니다. "순위추적" 탭은 예정된 기능의 미리보기 화면만 제공하며 현재 실제 순위 조회 기능은 없습니다.

## 8. Excel 출력

수집 결과가 1건 이상이면 Excel 파일로 저장합니다. **수집 결과가 0건이면 Excel 파일을 만들지 않습니다**(빈 파일을 남기지 않음).

저장 경로 예시(파일명은 화면에서 지정한 저장 경로 기준으로, 실행 시각 타임스탬프가 자동으로 붙습니다):

```text
output/<파일명>_YYYYMMDD_HHMM.xlsx
```

3개 시트로 저장됩니다:

- **통합_결과**: 주 산출물 시트. 아래 14컬럼이 이 순서로 들어갑니다.
- **원본_모바일**, **원본_PC**: 과거 구조를 유지하기 위한 시트로, 현재는 항상 헤더만 있는 빈 시트로 저장됩니다.

| 컬럼명 | 설명 |
|---|---|
| 업체명 | 검색 목록 응답 기준 업체명 |
| 업종 | 카테고리(추출 불안정, 빈 값 허용) |
| 새로오픈여부 | O(신규 오픈 확인)/X(아님)/빈 값(확인 안 됨) |
| 방문자리뷰수 | 확인되지 않으면 빈 값(0과 구분) |
| 블로그리뷰수 | 확인되지 않으면 빈 값(0과 구분) |
| 총리뷰수 | 방문자+블로그가 모두 확인됐을 때만 채워짐 |
| 주소 | 목록 기준 주소, 지역명 중복 제거·건물명 보존 |
| 대표전화 | 개인 휴대전화 제외, 일반 유선/공식 가상번호 우선 |
| 플레이스 URL | 업체 상세 페이지 URL |
| 수집일 | 수집 실행일(YYYY-MM-DD) |
| 홈페이지 | 대표 외부 링크 중 인스타/블로그가 아닌 홈페이지 |
| 인스타 | `instagram.com` 링크 |
| 블로그 | `blog.naver.com` 등 블로그 링크 |
| 추가 링크 | 대표 3링크 외 채널(카카오채널/유튜브/페이스북/스마트스토어/기타 등) - `[채널명] URL` 형식, 여러 건이면 줄바꿈으로 구분 |

값이 없는 필드는 빈칸일 수 있습니다. "빠른 기본 수집" 모드에서는 홈페이지/인스타/블로그/추가 링크가 목록 응답에 값이 있는 경우를 제외하면 대부분 빈칸입니다(§3).

제외 항목(수집하지 않음): 영업시간, 평점, 대표자명, 개인 휴대폰 번호, 개인 이메일.

## 9. 안전 중단과 부분 저장

CAPTCHA(보안 확인)·요청 제한(429)이 감지되면 이를 우회하려 시도하지 않고 즉시 중단합니다. 어떤 중단 상황에서도 **수집된 결과가 1건 이상 있을 때만 저장됩니다**.

| 상황 | 저장 여부 |
|---|---|
| 전체 목표 개수 도달 | 저장 |
| 선택한 검색 조합을 모두 실행(목표 미달 가능) | 저장 |
| CAPTCHA(보안 확인) 감지 | 즉시 중단, 결과가 있으면 저장 |
| 요청 제한(429) 감지 | 즉시 중단, 결과가 있으면 저장 |
| 브라우저 페이지 오류 | 즉시 중단, 결과가 있으면 저장 |
| 사용자 중지 버튼 | 즉시 중단, 결과가 있으면 저장 |
| 홈페이지·SNS 보강 중 CAPTCHA/HTTP 403·405·429 | 보강만 즉시 중단, 이미 보강된 결과 + 아직 보강하지 않은 원본 목록 결과를 함께 저장 |

CAPTCHA/429 감지 시 프로그램은 이를 해결하거나 회피하려고 시도하지 않습니다. 짧은 시간에 반복 실행하지 말고 잠시 후 다시 시도하세요.

## 10. 현재 제한사항

- 키워드는 1개만 지원합니다(다중 키워드 동시 수집 불가).
- 시도/시군구는 단일 선택만 가능합니다(여러 시군구를 한 번에 조회할 수 없음).
- 업종 추출은 불안정할 수 있으며 빈 값으로 출력될 수 있습니다.
- 전체 목표 저장 개수는 최대 목표값이며 보장값이 아닙니다. 지역·업종·검색 결과 상태에 따라 미달할 수 있습니다.
- 새로오픈 업체만 수집 필터를 켜면 새로오픈 전용 목록만 수집하며, 새로오픈 업체가 적은 지역에서는 목표보다 적은 결과가 정상일 수 있습니다.
- 네이버의 화면·응답 구조가 바뀌면 수집이 실패하거나 일부 필드가 비어 있을 수 있습니다.
- Microsoft Edge/Chrome 프로세스나 전용 프로필 상태(다른 인스턴스 실행 중 등)에 따라 실행이 지연되거나 오류가 날 수 있습니다(§5).
- "홈페이지·SNS 포함 수집" 모드는 기본 모드보다 느립니다.
- "순위추적" 탭은 준비 중인 기능의 미리보기 화면만 제공합니다.
- 대량/반복 수집은 네이버 이용약관 위반 가능성이 있으니 자제해야 합니다.
- 데이터 수집·활용에 관한 법적 책임은 `LEGAL_NOTICE.md`를 반드시 확인하세요.

### 법정동 공식 데이터 갱신(개발자용)

평소 프로그램(`app.py`) 실행은 행정안전부 API를 전혀 호출하지 않습니다. 최종 사용자는 API 키가 필요 없으며, 아래 스크립트는 개발자가 공식 법정동 데이터를 미리 갱신해두는 별도 도구입니다. 프로그램은 이 도구가 만든 로컬 Snapshot 파일(`data/legal_dong_snapshot.json`)을 읽기 전용으로 사용합니다.

```powershell
# Dry Run(기본, snapshot 미변경) - 변경 보고서만 생성
.\.venv\Scripts\python.exe scripts\update_legal_dong_snapshot.py

# Apply(검증된 결과로 Snapshot 교체)
.\.venv\Scripts\python.exe scripts\update_legal_dong_snapshot.py --apply
```

`.env`에 `DATA_GO_KR_SERVICE_KEY=<공공데이터포털에서 발급받은 키>`를 설정해야 합니다(`.env.example` 참고). 키가 없으면 네트워크 호출 없이 안내만 출력하고 종료합니다. 서비스키를 Git에 올리지 마세요 - `.env`는 `.gitignore`에 포함되어 있습니다.

## 12. EXE 빌드

```powershell
# 사전: .venv 활성화 + playwright install chromium 완료 상태에서
.\build.bat
```

`build.bat`은 `NaverPlaceSalesDBCollector.spec`(공식 법정동 Snapshot을 EXE 내부에 번들하는 빌드 계약)으로 PyInstaller를 실행한 뒤, `dist/ms-playwright/`에 브라우저 번들을 복사합니다.

- 빌드 후 `dist/NaverPlaceSalesDBCollector.exe`와 `dist/ms-playwright/`가 생성됩니다.
- **배포 시 EXE와 `ms-playwright` 폴더를 반드시 같은 폴더에 함께** 두어야 합니다.
- 수집 결과 Excel은 EXE가 실행된 위치 기준 `output/` 폴더에 저장됩니다.
- EXE 실행 시에는 진단 모드가 자동으로 비활성화됩니다(브라우저는 화면 밖에서 동작, 진단 산출물 저장 없음).
- 최초 실행 시 내부 압축 해제로 수 초~수십 초가 걸릴 수 있습니다. 일부 백신이 PyInstaller onefile EXE를 오탐할 수 있습니다.

> 이 빌드 계약은 저장소에 존재하며 관련 테스트도 있지만, 이 문서는 빌드 스크립트/spec의 선언 내용만 확인한 것입니다. 최신 실제 EXE 재빌드·실행 검증 여부는 `PROJECT_STATE.md`를 확인하세요. "모든 PC에서 실행이 보장된다"는 의미는 아닙니다.

## 14. 법적·운영 주의사항

- 대량/반복 수집은 네이버 이용약관 위반 가능성이 있으니 자제합니다.
- CAPTCHA·요청 제한(429)이 감지되면 우회하지 않고 즉시 중단하며, 그때까지 수집된 결과가 있으면 저장합니다(0건이면 파일 미생성).

- 수집된 데이터의 활용 방법과 법적 책임 범위는 반드시 `LEGAL_NOTICE.md`를 확인하세요.
